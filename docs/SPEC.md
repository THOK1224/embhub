# SPEC — embhub 应该成为什么

> **这份文档的定位**：`README.md` 说项目**现在是什么**，`LOG.md` 说项目**怎么变成现在这样的**，本文件说项目**应该成为什么**——设计原则、模块契约、边界与验收标准。
> **版本**：v0.1，写于 Phase 0 spike 尚未通过时。**架构部分与语言选择无关**（技术栈决策记录已确认：无论 spike 成败，架构与五个核心抽象都不变），因此先立此文件；若 spike 失败切回 Python 路线，第 3 节的契约（语言中立）照旧成立，只有「实现形态」示例需要改写。
> **优先级**：本文件与本文件引用的 `docs/PLAN.md` 冲突时，以本文件为准；与 `AGENTS.md` 冲突时，以 `AGENTS.md` 为准。

---

## 1. 这个项目应该成为什么

三句话：

1. 一个**能把「板子上的字节」变成「可检索的证据」**的桌面工作台：抓到的日志不只是文本，而是带设备、时间、固件出处的结构化记录。
2. 它的不可替代性在**关联**，不在采集：任何一份日志都能回答「哪个设备、什么时候、**哪次提交构建的哪个 bin**、用什么解析器」。
3. 它必须**能在没有硬件的情况下被验证**：采集到的任何东西都能离线重放，且重放结果与实时逐字节一致。

---

## 2. 设计原则

每条都可检验，不是口号。

1. **core 不依赖 UI。** `embhub-core` 的依赖树里不出现 tauri/窗口/IPC 相关 crate。检验方式：一条测试读自己的 `Cargo.toml` 并断言。
2. **接口是测试面。** 调用方与测试跨同一个 seam。想绕到接口背后测试，说明模块形状错了。
3. **一个实现提示的 seam 是假 seam，两个实现才是真 seam。** 只有 `ByteSource`（串口/SSH/回放/RTT）与 `LogStore`（真实/内存假件）有资格做 seam；其余地方直接写死具体类型。
4. **落盘路径无损优先。** 显示层可以丢帧（必须提示丢了多少），落盘层一个字节都不能丢。两者从采集点就分开，不允许共用一条会阻塞的队列。
5. **时间戳在到达点打。** 字节到达数据源线程的瞬间打单调时钟；解析、落盘、显示都不许改写它。UI 渲染时间永远不是数据时间。
6. **可重放是默认能力，不是附加功能。** 任何实时会话都必须能离线重放，走同一条解析与落盘管线。不能重放的数据，等于没抓到。
7. **配置与状态分离。** 工程文件（`.embproj`）只存可复现的配置；滚动位置、窗口大小这类状态不进去。

## 3. 模块契约

术语按 `codebase-design` 的定义使用：**module**（有接口与实现的任何东西）、**interface**（调用方必须知道的一切：签名、不变量、顺序约束、错误模式、性能特征）、**depth**（接口上的杠杆）、**seam**（接口所在的位置）、**adapter**（在 seam 上满足接口的具体物）。

接口在这里**首先是一组必须成立的约定**；Rust 签名只是它的实现形态示例，不是契约本身。

### 3.1 `ByteSource` —— 字节流来源

**职责**：把一个字节来源变成有序的字节块序列。

**Interface**

| 项 | 约定 |
| --- | --- |
| 操作 | `open(config) -> Result<Self>`；`read(&mut buf) -> Result<usize>`（阻塞，0 表示当前无数据）；`close()`（幂等） |
| 时间戳 | 每个返回的块**自带到达时刻**（单调时钟）。调用方不得改写 |
| 边界 | 块边界**任意**：解析器必须自己处理半帧。来源不得承诺「一次 read 一帧」 |
| 所有权 | 复用调用方提供的缓冲区；稳态读取路径**不分配堆内存** |
| 错误模式 | 必须把「暂时无数据（超时/0 字节）」与「致命断开（设备拔出、连接重置）」**分开**。前者不是错误 |
| 吞吐 | 持续 ≥ 1 Mbps 不丢字节（用「收到的字节数 == 发送的字节数」检验，不靠肉眼看） |
| 关停 | `close` 后不再返回数据；在途的读要么返回，要么以「已关闭」结束，不允许 panic |

**Adapters（真 seam，两种以上）**：`SerialSource`（serialport-rs）、`SshChannel`（russh exec/shell）、`ReplaySource`（读 `LogStore` 的分片）、`RttSource`（`probe-rs` 子进程输出，Phase 7）。

> `ReplaySource` 与 `SerialSource` 实现**同一个** interface，是原则 6 的结构保证：能实时看的就能重放。

### 3.2 `Parser` / `Frame` —— 解析

**职责**：把字节流变成结构化记录。

**Interface**

| 项 | 约定 |
| --- | --- |
| 操作 | `push(&mut self, bytes) -> Vec<Frame>`；`flush(&mut self) -> Vec<Frame>` |
| `Frame` | `{ t_mono（来自来源，不改写）, raw（原始字节范围）, fields（解析出的字段）, session_id, fingerprint_ref }` |
| **纯性** | **同一字节序列必须产出同一 `Frame` 序列。** 解析器不得依赖墙上时钟、随机数、外部 I/O。这是「实时 == 回放」可被断言的前提 |
| 残帧 | `push` 必须把未凑成整帧的字节留在内部缓冲；不得丢弃 |
| 畸形输入 | **永不 panic**。畸形数据产出带错误标记的 `Frame`，且错误不得中断后续解析 |
| 回溯源 | 每个 `Frame` 必须能定位回原始字节偏移（否则「解析结果可回溯」无法验收） |

**内建解析器**：行协议、分隔符、HEX、定长帧、带校验和的帧。扩展解析器由 `plugins/` 注册（Phase 6）。

### 3.3 `LogStore` —— 落盘与回放

**职责**：把原始字节持久化，并能精确读回来。**这是全项目 depth 最高的模块**：接口只有四个操作，背后是分片、索引、崩溃恢复与并发。

**Interface**

| 项 | 约定 |
| --- | --- |
| 操作 | `create_session(meta) -> SessionId`；`append(id, chunk) -> Result<()>`；`seal(id)`；`open_replay(id, range) -> ByteSource` |
| **持久性** | `append` 返回 `Ok` 的语义必须**明确定义**（写进缓冲区 / 落到文件 / fsync 三级中选一级并写进文档）。**不允许含糊**——「以为落盘了其实没有」是本项目最不可接受的失败 |
| 日志头 | 每个会话开头写：**格式版本号**、指纹、来源配置、起始墙上时钟 |
| 分片 | 按大小（默认 64 MiB）或时间（默认 5 分钟）切分；每片带校验和 |
| 崩溃恢复 | 进程被强杀后，已 `seal` 的分片必须完整可读；未 seal 的分片必须能判定出**有效前缀**，不允许把半条记录当成完整数据 |
| 并发 | 单写者、多读者；写路径不得阻塞 UI 侧的读路径 |
| 回放 | `open_replay` 返回的 `ByteSource` 必须重建**原始字节序列与时间戳**，与实时采集时一致 |
| 索引 | SQLite（`rusqlite` + `bundled`）存会话元数据、帧偏移、指纹；原始字节永远在分片文件里，不塞进数据库 |

**深度检验（deletion test）**：删掉这个模块，分片、校验、崩溃恢复、索引、回放会在每个 sink 与每个 UI 面板里重新长出来——所以它必须存在。

### 3.4 `Session` —— 会话

**职责**：把「一个来源 + 一条解析链 + 一组 sink + 元数据」绑成一个可保存、可启停的单元。

**Interface**

| 项 | 约定 |
| --- | --- |
| 操作 | `start` / `stop` / `status` / `config_snapshot` |
| 状态机 | `Created → Running → Stopped`；`Stopped → Running` 允许重启；`Running` 时禁止改配置（改配置 = 新建会话） |
| 互斥 | 同一物理端口**不得被两个 Session 同时持有**。冲突必须在校验阶段就报错，而不是等打开失败 |
| 确定性释放 | 停止即释放句柄与线程；不允许「僵尸读取线程」继续往已关闭的 store 写 |
| 序列化 | `Session` 的配置可存为 `.embproj`，在另一台机器上可复现打开（原则 7） |
| 指纹 | 会话创建时采集一次并写入日志头；采集失败**不阻塞会话**，但必须记录失败原因（不允许出现「看着有指纹、其实是空的」） |

> 同一台机器可以同时跑 N 个 Session（调研 C2 的多设备场景），它们互不干扰。

### 3.5 `FirmwareFingerprint` —— 固件指纹

**职责**：回答「这段日志是哪个 bin 跑出来的」。这是本项目区别于所有竞品的那一件事。

**Interface**

| 字段 | 约定 |
| --- | --- |
| `repo_root` / `commit` / `dirty` | 由系统 `git` CLI 取得（`rev-parse HEAD`、`status --porcelain`）。`dirty = 输出非空` |
| `bin_path` / `bin_hash` | `bin_hash` 是**文件内容**的哈希，不是路径或时间戳 |
| `build_time` | 构建产物时间，与 `commit` 一起构成人的可读标识 |
| `chip` / `probe_id` | 目标芯片与调试器序列号（Phase 7 填） |
| 采集时机 | **会话创建时**，结果写入日志头。事后补是补不回来的 |
| 失败语义 | 任一字段取不到 → 记 `None` + 失败原因字符串；**不允许静默省略** |

### 3.6 依赖方向

```
embhub-app (Tauri) ──► embhub-core ◄── embhub-cli
                          │
        ┌─────────────────┼──────────────────┬───────────────┐
     source/           parse/             store/        fingerprint/ ──► vcs/
```

**规则**：箭头只允许单向。`core` 不知道 Tauri、不知道 CLI、不知道 HTTP。任何反向依赖都是设计事故。

**内部 seam 自律**：只在 3.1 与 3.3 设 seam。`Session` 内部直接持有具体类型（一个实现提示的 seam 是假 seam，只会增加间接层）。

## 4. 术语表

写代码、写文档、写测试都用这几个词，不要换同义词。

| 词 | 含义 |
| --- | --- |
| **零丢失** | 落盘路径永不丢字节；显示层可丢，但必须报出丢了多少 |
| **可重放** | 任何实时会话都能在没有硬件的情况下重新走完解析与落盘管线 |
| **指纹** | `FirmwareFingerprint` 的简称，即「这段日志对应哪个 bin」 |
| **到达时间** | 字节抵达数据源线程的单调时钟读数；不是 UI 渲染时间，不是文件写入时间 |
| **seam** | 接口所在的位置；本项目只有两处 |
| **深度** | 接口上的杠杆（小接口背后大行为），不是「实现行数 / 接口行数」 |

## 5. 边界

**在范围内（按阶段推进）**：串口采集与落盘、可重放日志、固件指纹、会话模型与多设备、内建解析器、SSH/SFTP（干活用，非通用终端）、Git 溯源关联、烧录与 RTT 编排（可选）。

**明确不在范围内**：

- 通用终端仿真器的全功能对标（Tabby / WezTerm / Alacritty 的地盘）。
- 「又一个 Git GUI」（Lapce / VS Code 的 Git 面板已经够好）。本项目的 Git 价值只在**关联**。
- 云同步、账号体系、自动更新、团队协作。
- X11 / RDP / VNC。
- 需要内核过滤驱动的功能（例如被动监听已被占用的串口）——**在验证其可行性前不承诺**（见 `docs/PLAN.md` Phase 2 的 spike 与风险 R5）。

## 6. 验收标准

**因为这个项目的维护者不读代码，验收必须是可执行的脚本，而不是「看起来对」。** 每条都给出可运行命令或明确的判定方式。

| # | 标准 | 判定方式 |
| --- | --- | --- |
| A1 | core 可独立测试，且不含 UI 依赖 | `cargo test --offline -p embhub-core` 全绿；一条测试断言 `Cargo.toml` 中无 tauri |
| A2 | 无硬件也能验证 | 全部核心测试在没有任何串口设备的机器上通过（用 `ReplaySource` + 录制字节流） |
| A3 | 零丢失 | 注入 N MB（N ≥ 100）后，断言「落盘字节数 == 注入字节数 == 解析消耗字节数」；三处计数不一致即失败 |
| A4 | 实时与回放一致 | 同一份录制数据，实时路径与回放路径产出的 `Frame` 序列**逐字节相同** |
| A5 | 崩溃恢复 | 在 `append` 过程中强杀进程，重启后已 seal 分片完整可读、未 seal 分片能给出有效前缀 |
| A6 | 日志可回答四问 | 任取一份落盘日志，用 `embhub-cli` 回答：哪个设备、什么时间、哪次提交的哪个 bin（含 hash）、用了哪个解析器 |
| A7 | 无头端到端 | `embhub-cli` 能跑通「打开来源 → 抓 N 秒 → 落盘 → 回放校验」并给出退出码 |
| A8 | 绿色便携 | 整个过程不写注册表；配置目录可整体拷贝到另一台机器使用 |
| A9 | 静态检查 | `cargo clippy --all-targets -- -D warnings` 与 `cargo fmt --check` 干净 |

## 7. 尚未定的（明确列出，不假装完整）

1. **`append` 的持久性等级**（缓冲 / 落文件 / fsync）——需在 Phase 1 结合吞吐实测决定，并在实现里写死为文档中的明确语义。
2. **分片大小与时间的默认值**——当前写 64 MiB / 5 分钟是**初值，未实测**。
3. **`.embproj` 的具体 schema**——Phase 2 定。
4. **IPC 吞吐是否够用**——若不够，是否引入本地 WS 网关（`docs/PLAN.md` 风险 R9）。
5. **`Frame.fields` 的表达方式**（固定枚举 / 动态 map / 借用原始缓冲）——影响解析器性能与解析器插件接口，Phase 3 定。
6. **Windows 上被动监听已占用串口的可行性**——结论未知，Phase 2 的 spike 决定是否砍掉。
